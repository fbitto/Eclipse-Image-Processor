# AEL NAFE

`core/ael_nafe.py` copies/adapts AEL 1.4.2 `filters.nafe_neighbourhood`, `filters.nafe` and `filterbank.nafe_noise_sigma`, Copyright (c) 2026 Pere Guerra Serra, MIT. See [attribution](../ATTRIBUTIONS.md) and the [retained license](third-party/AEL-MIT.txt). The upstream package is not a dependency. No new dependency is installed.

## Input, operator and layer

Input is an already stacked linear HDR, using the same immutable working mono as every other branch (RGB luminance 0.299R + 0.587G + 0.114B). No RAW calibration, registration, stacking or per-exposure processing is involved. Display EV, Asinh, opacity, colour and prominence changes do not enter the operator. The source, canvas and separate prominence RGB/alpha are preserved.

Druckmüller (2013), ApJS 207, 25, equations 11–14: for each target, calculate the neighborhood-weighted mean of `Phi((I_target - I_neighbor)/sigma)`, where Phi is the Gaussian CDF and only observed operator samples contribute. This is the equalized image E in [0,1], float32, with a constant mapping to 0.5. The odd support kernel contains twelve Gaussians, sigma `2^(m/2)` target pixels for m=1…12, all c_m=1, normalized to centre 1. Sigma is an intensity-noise gate, distinct from spatial kernel sigma.

E is encoded directly as an independent Overlay layer with separate unassociated alpha; it is not MAD/tanh remapped. Overlay is an application presentation choice, not the paper's linear gamma/E mixture. Layer order places NAFE after NRGF and before FNRGF; all numerical branches still read the same source. New sessions leave NAFE disabled, at 20% opacity. Basic hides/disables it; Standard offers activation and opacity; Expert exposes its parameters. Leaving Expert retains hidden parameter values.

## Noise and units

Automatic sigma defaults to 12 times 1.4826 MAD of residuals from a normalized Gaussian with sigma 4 native pixels, measured outside 4 reference radii. These are AEL's defaults, not the different Nikon handoff parameters. With fewer than 20,000 region samples, use the outermost fifth of observed radii and record the change. After Gaussian support checking, fewer than 64 residual samples or zero measured noise uses an explicitly recorded input-relative numerical floor. This small-sample safeguard is a local extension. Automatic noise is empirical and may include coronal structure; it is not propagated photon uncertainty or proof of an empty-sky region.

Manual gate sigma is in normalized **working linear input units**, not detector DN/s. Expert's editor allows 0.000001…1; changing the linear intensity scale requires changing sigma proportionally. The direct numerical API accepts other finite positive sigma values. Native normalization bounds are shared across resolutions; presentation EV does not change sigma. Internal pedestal removal and shared image/sigma rescaling prevent extreme-unit overflow, without applying a nonlinear curve. Samples outside the operator mask cannot change the result or estimator.

## Masks and resolutions

NAFE intersects observed validity and the existing statistical/exclusion mask for its actual kernel samples. Missing samples never become zero-valued observations. It does not use the experimental AEL support-separation toggle: statistical exclusions always remove NAFE kernel samples. Output targets are separate finite observed pixels, including valid limb pixels inside the reference circle. The circle is not a replacement for observed validity and does not impose a second hard layer-alpha boundary. Query-only targets need at least 1% of the full weighted kernel support; they remain undefined when there are insufficient neighbors. Their measured intensity selects a fuzzy-CDF value but never enters the histogram or automatic-noise population. Layer alpha uses finite supported output without replacing source validity or the prominence mask. An empty operator domain is transparent.

Window choices are 65, 129 (default), 257 and 513 native pixels. Fast preview scales the window's half-width to target pixels and rounds to an odd size. Noise-residual smoothing also scales to target resolution. **The twelve internal Gaussians remain 1.414…64 target pixels.** Scaling only the support window does not preserve their native footprint. Reduced and 50% views are explicitly approximate; native verification/export recompute the configured native window, rather than enlarging a preview. Automatic noise is estimated separately at the target resolution and can differ after resampling. Receipts record target scale, effective/native window, internal scales and the noise choice.

## Runtime, settings and export

AEL's level step is fixed at 0.005, with intensity levels sigma/2 apart in the low range, then logarithmically spaced. E is linearly interpolated between levels, not an exact per-pixel summation of every neighbor. Frozen-source parity and a separate direct fuzzy-CDF test qualify that approximation.

FFT convolution is zero-padded: no reflected boundary radiance or inpainting. FFT workers follow the existing per-filter CPU budget. Up to two intensity levels execute concurrently, with at most two submitted tasks and results consumed in their original order. Each level receives half the live parent CPU budget, so cores released by other layers remain available. A one-core budget or the existing memory-budget helper can select sequential execution. The memory estimate is 64 bytes per padded FFT pixel per level, bounded to a quarter of physical RAM (1 GiB if RAM is unknown); it is a conservative heuristic, not an allocation guarantee. Receipts record `level_workers`. Cancellation is checked between levels and FFTs, contexts propagate to helpers, and queued tasks are cancelled and workers joined on completion or failure. An unfinished result cannot enter the cache. Existing inter-layer concurrency/memory limits still apply. Native large-image runtime depends on intensity range, sigma, window, field and hardware.

Numerical `nafe_*` parameters, geometry and masks participate in the existing cache signature. Activation, opacity and display changes only recompose cached results. Settings use the existing version-4 envelope; old recipes without NAFE controls reset it to disabled, automatic noise and window 129, without inheriting the preceding image's edits. TIFF/JPEG, TIFF layer packages and PSB use the same independent layer and mapping receipts. Direct `apply_filter` rejects NAFE because that legacy dispatcher returns source-intensity results; use `nafe` for E or the independent layer engine for composition.

Fixture provenance is in [the oracle notes](../tests/fixtures/ael_nafe_142.md).

These tests establish implementation and integration behavior, not independently recovered fine detail, increased resolution or astronomical SNR. Fine-scale noise and coverage-dependent texture can still become visible. Inspect the native result, limbs, coverage boundaries and corners before choosing opacity for a particular HDR.

Initial integration validation on 5 November 2026: all **469 repository tests passed**, including 11 NAFE tests. The frozen AEL small-scene oracle agrees within 2e-6. On the handoff's native 5801 × 4596 already stacked HDR, using its linear green channel, supplied operator mask, manual sigma 1285.422887109375 DN/s and window 257, the port matched the previously saved AEL NAFE E layer with maximum absolute difference **8.3446503e-7** (tolerance 3e-6). Both used 321 levels and 273 convolutions. The source SHA-256 remained `3aa7df518b2b0d4b5533aa037faa0455933f9530953d17696c2af3cf1731e4dd`. This checks the operator on the handoff input; it does not assert the GUI's weighted-RGB input equals that green-channel recipe.

Synthetic TIFF/JPEG, TIFF package and exact PSB channel/composite checks passed. Automatic/manual control state and Expert/Standard layouts were checked offscreen. No application rebuild, Windows run, native Photoshop acceptance or new independent scientific-detail qualification was performed.

## Two-level performance control

On the native handoff HDR, an isolated single-pair benchmark used the same 10-core total budget, sigma, window, 321 levels and 273 convolutions. Sequential levels took 177.62 s at 2.82 GiB peak RSS; two concurrent levels with five FFT workers each took 110.13 s at 3.61 GiB. That is a 1.61× speedup (38.0% less numerical time), with 0.79 GiB additional peak RSS. Output and undefined support matched exactly. Input loading and validation were outside the timer, and strategies ran sequential-first in separate processes without an overlapping test suite. This is evidence for this image/machine, not a universal speedup guarantee. The production scheduler retains the tested level plan and interpolation; concurrency changes execution only, without changing settings identity or numerical cache keys.

Production scheduler validation on 5 November 2026: **473 repository tests passed**, including 15 NAFE tests. New controls cover exact serial/parallel output and convolution-count parity on regular, sparse and constant scenes, low-memory and single-core fallback, bounded partial consumption, live callable CPU budgets, cancellation and worker-failure cleanup without cache publication. The native handoff check selected two level workers, retained 321 nodes/273 convolutions and matched the saved AEL layer within 8.3446503e-7; the HDR source hash was unchanged. That production check took 107.25 s while the full suite ran in another process, so it is a parity validation rather than a controlled repeat of the performance pair above. No new application rebuild or Windows/native-editor acceptance was performed for this scheduling change.

## Observed limb versus reference circle

A reported bright rim was reproduced on the margin −2 HDR at reference geometry (3013, 1688, 273). Its actual observed limb extends inside the reference circle: 7,626 finite pixels were being excluded from both NAFE output and alpha by the circular cutoff. At high opacity that left a visible strip of unfiltered base. The correction retains statistical/kernel exclusions but queries the CDF at all observed output targets. It changes no lunar geometry, blurs no RGB pixels and fills no missing radiance. Separate prominence RGB/alpha are unchanged.

The direct numerical API retains AEL behavior when `target_valid` is omitted. Optional observed targets are an EIP extension. Additional intensity nodes can extend the query range without moving the existing sample-grid nodes, preserving already calculated sample outputs. Tests cover below/above-population target values, nonparticipation in kernel statistics, missing targets, insufficient neighborhood support and an asymmetric observed limb inside the reference circle.

On the real source, native limb and reduced full-canvas comparisons at 60% opacity restored all 7,626 observed limb targets. The previously processed sample output was exactly unchanged in both comparisons; no missing pixel received output, and source SHA-256 remained `39f1544b4e7485f05e91b08282b74f0cdb48fde8c0810be781b3b5192dbf7ac1`. These are monochrome causal diagnostics using the native presentation scale, not a reproduction of the screenshot’s unspecified colour calibration/exposure or a new fine-detail certification.

The complete regression suite passed **475 tests** after the limb correction. The final focused run passed **17 NAFE tests**, including the additional below-population query and invalid target-shape controls. Native colour/Photoshop acceptance remains pending; the correction is qualified for the demonstrated circular-cutoff artifact, not every possible limb fringe.
